# DocFusion 项目改进建议

> 基于项目代码审查 + VPS (186.241.72.140) 线上部署状态综合分析  
> 编写日期：2026-05-28

---

| 组件 | 技术栈 | 部署方式 | 状态 |
|------|--------|----------|------|
| Main API | FastAPI + SQLite + SQLAlchemy | systemd 服务 | ✅ 运行中 |
| Toolkit API | FastAPI + Docker | 容器 (host网络) | ✅ 运行中(healthy) |

## 二、紧急问题 (P0 - 立即处理)

### 2.1 磁盘空间不足

**现状**: 磁盘使用率 85%，仅剩 4.6GB 可用空间。  
**风险**: SQLite 写入失败、Docker 镜像无法构建、日志撑满磁盘导致服务崩溃。

**建议**:
- 清理无用的 Docker 镜像: `docker system prune -a`
- 设置日志轮转(已配置 10MB/5份，但需确认实际执行)
- 定期备份后清理 `/opt/docfusion-main-api/backend/data/backups/`
- 考虑升级磁盘或挂载外部存储

### 2.2 API Key 明文暴露

**现状**: `.env` 文件中 OpenAI API Key 以明文存储 (`sk-CDXr...`)。  
**风险**: 任何有服务器访问权限的人都能读取。

**建议**:
- 使用 Docker Secrets 或 systemd `LoadCredential=`
- 或使用 Vault/Infisical 等密钥管理服务
- 至少确保 `.env` 文件权限为 `0600`（当前 `.env` 权限是 `0640`，应缩紧）

### 2.3 Main API 缺少 `/docs` 端点

**现状**: 访问 `http://localhost:8000/docs` 返回 404。  
**影响**: 无法在线查看 API 文档，不利于开发调试。

**建议**:
- 在 `backend/api/server.py` 中启用 FastAPI 默认的 Swagger UI:
  ```python
  app = FastAPI(docs_url="/docs", redoc_url="/redoc")
  ```
- 生产环境可通过环境变量控制是否暴露

## 三、安全加固 (P1)

### 3.1 Nginx 版本过低

**现状**: Nginx 1.18.0 (2020年发布)，已知多个安全漏洞。  
**建议**: 升级到 1.24+ 或使用 Ubuntu PPA 获取最新稳定版:
```bash
add-apt-repository ppa:ondrej/nginx
apt update && apt upgrade nginx
```

### 3.2 SSH 安全加固

**现状**: 允许 root 密码登录。  
**建议**:
- 禁用 root 密码登录，仅允许密钥认证
- 配置 fail2ban 防止暴力破解
- 更改 SSH 端口(非必须但增加安全性)

```bash
# /etc/ssh/sshd_config
PermitRootLogin prohibit-password
PasswordAuthentication no
```

### 3.3 Docker 容器安全

**现状**: Toolkit 容器使用 host 网络模式，无端口隔离。  
**建议**:
- 改用 bridge 网络 + 仅暴露 8010 端口到 localhost:
  ```bash
  docker run --network bridge -p 127.0.0.1:8010:8010 ...
  ```
- 添加 `--read-only` 标志(只读根文件系统)
- 限制容器资源: `--memory=2g --cpus=2`

### 3.4 CSRF 与速率限制

**现状**: 无 API 速率限制，外部 IP 132.226.104.211 频繁访问。  
**建议**:
- Nginx 层添加速率限制:
  ```nginx
  limit_req_zone $binary_remote_addr zone=api:10m rate=30r/m;
  location /api/ {
      limit_req zone=api burst=10 nodelay;
      ...
  }
  ```
- 或在 FastAPI 层使用 `slowapi` 中间件

## 四、架构优化 (P1)

### 4.1 数据库迁移方案

**现状**: SQLite 单文件数据库(64KB)，无数据迁移工具。  
**问题**: 
- 表结构变更需手动操作
- 无法回滚
- 多人开发时 schema 不一致

**建议**: 引入 Alembic 做数据库版本管理:
```bash
pip install alembic
alembic init migrations
alembic revision --autogenerate -m "initial"
alembic upgrade head
```

### 4.2 异步 I/O 优化

**现状**: `DocumentParser.parse()` 和文件操作是同步的，阻塞 FastAPI 事件循环。  
**建议**:
```python
# 将阻塞操作移到线程池
from asyncio import to_thread
result = await to_thread(parser.parse, file_path)
```

### 4.3 前端 UI 模块化

**现状**: `DocFusionWindow` 单个类超过 2000 行。  
**建议**: 拆分为独立组件:
```
frontend/
  pages/
    document_page.py      # 文档管理
    entity_page.py        # 实体提取
    template_page.py      # 模板填充
    commander_page.py     # 文档指令
    crawler_page.py       # 爬虫管理
  widgets/
    log_viewer.py
    file_browser.py
    settings_dialog.py
```

### 4.4 健康检查统一化

**现状**: Main API 有 `/api/health`，Toolkit 有 `/healthz`，不统一。  
**建议**: 统一为 `/healthz` (存活检查) + `/readyz` (就绪检查):
- `/healthz`: 进程存活
- `/readyz`: 依赖就绪(DB可连接、LLM可达)

## 五、运维改进 (P1)

### 5.1 添加 docker-compose.yml

**现状**: 手动 `docker run` 启动容器，无编排。  
**建议**: 创建统一编排文件:

```yaml
# docker-compose.yml
version: "3.8"
services:
  toolkit:
    build: ./server_toolkit
    image: docfusion-toolkit-api:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:8010:8010"
    volumes:
      - toolkit-tasks:/var/docfusion/tasks
    environment:
      - DOCFUSION_EXECUTION_BACKEND=local
    deploy:
      resources:
        limits:
          memory: 2G
          cpus: "2"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8010/healthz"]
      interval: 30s
      retries: 3

volumes:
  toolkit-tasks:
```

### 5.2 日志聚合

**现状**: 日志分散在 journald 和 Docker stdout。  
**建议**:
- 短期: 使用 `journalctl` 导出 + logrotate
- 中期: 部署 Loki + Promtail 收集所有日志
- 或使用轻量方案: `vector` → 本地文件/远程

### 5.3 监控告警

**现状**: 无监控系统，无法感知服务异常。  
**建议**:
- 轻量方案: 使用已有的 health check + cron + 邮件/webhook 通知
- 完整方案: Prometheus + Grafana (内存占用约 200MB)

```bash
# 简易监控脚本 /opt/docfusion-monitor.sh
#!/bin/bash
if ! curl -sf http://127.0.0.1:8000/api/health > /dev/null; then
  echo "DocFusion Main API DOWN" | mail -s "Alert" admin@example.com
fi
```

### 5.4 自动备份策略

**现状**: 有 backups 目录但无自动化。  
**建议**:
```bash
# /etc/cron.d/docfusion-backup
0 3 * * * docfusion sqlite3 /opt/docfusion-main-api/backend/data/docfusion.db ".backup '/opt/docfusion-main-api/backend/data/backups/docfusion-$(date +\%Y\%m\%d).db'"
# 保留 7 天
0 4 * * * docfusion find /opt/docfusion-main-api/backend/data/backups/ -name "*.db" -mtime +7 -delete
```

## 六、代码质量 (P2)

### 6.1 依赖清理

**现状**: `backend/requirements.txt` 同时声明了 PyQt6 和 PySide6。  
**建议**: 
- backend 不需要 GUI 框架，移除 PyQt6 和 PySide6
- 分离 `requirements-api.txt`（后端服务）和 `requirements-desktop.txt`（桌面端）

### 6.2 配置硬编码

**现状**: 多处硬编码 URL 和魔法数字。  
**示例**:
```python
# frontend/docfusion_page.py
DEFAULT_API_URL = "https://docx.zhuoruan.xyz/api"
# backend/core/entity_extractor.py
chunk_size = 3000  # 应为配置项
```

**建议**:
- 所有可变值通过 `config.py` 统一管理
- 添加 `.env.example` 文件记录所有环境变量

### 6.3 错误处理标准化

**现状**: 部分函数返回 `{"success": False, "error": "..."}`, 部分抛异常。  
**建议**: 统一使用异常 + 全局异常处理器:
```python
# 自定义异常层级
class DocFusionError(Exception): ...
class ValidationError(DocFusionError): ...
class LLMError(DocFusionError): ...

# FastAPI 全局处理
@app.exception_handler(DocFusionError)
async def handle_docfusion_error(request, exc):
    return JSONResponse(status_code=exc.status_code, content={"error": str(exc)})
```

### 6.4 测试覆盖率提升

**现状**: 仅有回归测试和部分单元测试，缺少集成测试。  
**建议**:
- 添加 API 端到端测试 (使用 httpx.AsyncClient + pytest)
- 添加 LLM 调用 mock 测试
- 设置覆盖率目标: 核心模块 > 80%
- CI 中运行 `pytest --cov`

## 七、功能增强 (P2)

### 7.1 批量处理进度反馈

**现状**: 批量文档处理时前端无实时进度。  
**建议**: 使用 WebSocket 或 SSE 推送进度:
```python
@app.get("/api/tasks/{task_id}/progress")
async def task_progress(task_id: str):
    async def event_stream():
        while not task.done:
            yield f"data: {json.dumps(task.progress)}\n\n"
            await asyncio.sleep(1)
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

### 7.2 多用户支持

**现状**: 单 token 认证，不区分用户。  
**建议**(如需多人使用):
- 引入 JWT 认证
- 添加用户表 + 权限模型
- 文档按用户隔离

### 7.3 LLM 调用可观测性

**现状**: LLM 调用无指标统计。  
**建议**: 记录每次调用的:
- Token 使用量(输入/输出)
- 响应时间
- 成功/失败率
- 费用估算

```python
# 简易实现
class LLMMetrics:
    total_tokens: int = 0
    total_cost: float = 0.0
    call_count: int = 0
    error_count: int = 0
```

### 7.4 文档版本控制

**现状**: 文档修改后无历史版本。  
**建议**: 在 Document Commander 操作前自动创建快照:
- 保存操作前文件的 SHA256
- 维护 `document_versions` 表
- 支持回滚到任意历史版本

## 八、部署流程优化 (P2)

### 8.1 CI/CD 流水线

**现状**: 无自动化部署，手动 scp + 重启服务。  
**建议**: 使用 GitHub Actions:

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run tests
        run: pytest
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.VPS_HOST }}
          username: root
          key: ${{ secrets.SSH_KEY }}
          script: |
            cd /opt/docfusion-main-api
            git pull origin main
            systemctl restart docfusion-main-api
```

### 8.2 蓝绿部署

**现状**: 重启服务会导致短暂不可用。  
**建议**: 使用 systemd socket activation 或 Nginx upstream 切换实现零停机。

### 8.3 环境一致性

**现状**: 开发环境(Windows)与生产环境(Linux)差异大。  
**建议**:
- 提供 `Dockerfile.dev` 用于本地开发
- 使用 `pyproject.toml` 统一依赖管理(替代多个 requirements.txt)

## 十、VPS 快速修复清单

以下操作建议立即在 VPS 上执行:

```bash
# 1. 清理磁盘空间
docker system prune -a --volumes
apt autoremove && apt clean
find /var/log -name "*.gz" -delete

# 2. 收紧 .env 权限
chmod 600 /opt/docfusion-main-api/.env
chmod 600 /opt/docfusion-toolkit/.env

# 3. 添加简易监控 cron
cat > /etc/cron.d/docfusion-healthcheck << 'EOF'
*/5 * * * * root curl -sf http://127.0.0.1:8000/api/health > /dev/null || systemctl restart docfusion-main-api
EOF

# 4. 添加数据库备份 cron
cat > /etc/cron.d/docfusion-backup << 'EOF'
0 3 * * * docfusion sqlite3 /opt/docfusion-main-api/backend/data/docfusion.db ".backup '/opt/docfusion-main-api/backend/data/backups/daily.db'"
EOF

# 5. 启用 Nginx 速率限制
# 在 /etc/nginx/nginx.conf 的 http {} 块内添加:
# limit_req_zone $binary_remote_addr zone=api:10m rate=30r/m;
# 然后在 location /api/ 块内添加:
# limit_req zone=api burst=10 nodelay;
nginx -t && systemctl reload nginx
```
