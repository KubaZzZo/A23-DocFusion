## 一、赛题要求与项目对照

| 模块 | 赛题要求 | 你的实现 | 完成度 |
|------|----------|----------|--------|

## 三、本会话已完成的改进

### 3.1 模块一加固 — Codex CLI 提升为主执行路径

**改前：** DocCommander 的执行路径是 规则→LLM JSON→Codex CLI回退，每层都不稳定。

**改后：** 新执行路径：

```
用户输入 → 规则匹配命中? → 直接执行 python-docx (0.1s, 简单指令)
         → 规则未命中?   → Codex CLI 写代码执行 (10-30s, 复杂指令)
                        → LLM JSON 解析 (最后兜底)
```

新增了 `CODEX_DOC_COMMAND_PROMPT`（完整的中文文档操作提示词，包含字体/颜色/对齐/东方字符处理），Codex CLI 现在可以直接读写文档、理解复杂操作、处理异常情况。

**修改文件：** `backend/core/doc_commander.py`, `backend/core/document_workflow.py`

### 3.2 server_toolkit agent.py — 从28行到功能完整

**改前：** 只能构建 prompt，不能执行。L3 任务直接报错 "not implemented"。

**改后：** 新增 `run_codex_agent()` 和 `run_codex_agent_with_files()`，真正调用 Codex CLI 执行 L3 任务。

**修改文件：** `server_toolkit/server_toolkit/agent.py`, `worker.py`, `plan_parser.py`

### 3.3 三个模块的串联工作流引擎

**新建文件：** `backend/core/workflow_engine.py`

提供三个预置工作流：
- `extract_and_fill` — 模块二(提取) → 模块三(填写) → 可选模块一(格式化)
- `full_pipeline` — 提取 → 跨文档融合 → 填写 → 格式化
- `batch_process` — 批量提取 → 数据融合 → Codex CLI生成汇总报告

**API 端点：**
- `POST /api/workflow/extract-and-fill` — 提取+填写
- `POST /api/workflow/full-pipeline` — 完整三模块串联
- `POST /api/workflow/batch-process` — 批量处理+融合报告

**修改文件：** `backend/api/routes.py`

### 3.4 准确率验证框架

**新建文件：** `backend/core/accuracy_validator.py`

- 加载人工标注的测试数据 (JSON格式)
- 运行提取 → 对比标注 → 计算 Precision/Recall/F1
- 分类型统计 + 整体评分 + 生成报告
- 附带样本标注文件生成器

